# engawa-bot

[English](README.md)

ブラウザだけで使える仮想オフィス [engawa](https://github.com/iitenkida7/engawa) に住む bot です。
にぎやかなフロアから少し離れたところでのんびり過ごし、ときどき散歩します。**ノックすると会議に来て**、
録画と文字起こしをし、あなたが部屋を出ると、録画・要約・文字起こし全文を届けます。

- **録画**: engawa の録画機能をそのまま使います（画面共有を大きく、カメラを横に並べる構成）。
- **文字起こし**: engawa の Groq Whisper 文字起こしをそのまま使います（話者ごとに「誰が何を言ったか」）。
- **要約**: Groq の LLM で、決まったこと・宿題・次の予定を中心にまとめます。
- **届ける**: Google の共有ドライブに置き、呼んだ人に会議フォルダを共有します（ドライブの通知メールに要点が載ります）。
  ローカルのフォルダに置くだけの設定もできます。

bot は engawa の**普通の参加者**として、人と同じように入室し、歩き、ボタンを押します。
そのため **engawa 本体には一切手を入れていません**。Bun 組み込みの
[`Bun.WebView`](https://bun.com/docs/runtime/webview) でヘッドレス Chrome 上の engawa を操作し、
周りの状況は engawa クライアント自身の WebSocket 通信から読み取ります。

## 動き方

1. 入室したら `STROLL_POINTS` のあたりで過ごし、数分おきに少しだけ移動します。人には近づきません
   （近づくと通話がつながってしまうため）。
2. ノックします（👥 参加者 → bot → ノック）。bot が応じて、engawa の機能であなたのところへ歩いてきます。
3. あなたと同じ通話に入ったら、録画と文字起こしを始めます。全員に、いつもの録画中・文字起こし中の表示が出ます。
4. **呼んだ人**が bot の通話から 15 秒抜けたら（部屋を出たら）終了し、録画と文字起こしを回収して待機場所に戻ります。
   会議の長さは `MAX_MEETING_MINUTES` で上限を設けています。
5. 裏で要約を作り、すべてを届けます。

会議中に別の人からノックされた場合は「あとで」で応じます（一度に 1 会議）。

ひと目で bot と分かるように、プロフィール画像はロボットの顔です（カメラオフのタイル・参加者一覧・マップ上の名前の横に出ます）。
アバターも帽子と眼鏡の決まった見た目にしています。`BOT_AVATAR_IMAGE` と `BOT_OUTFIT` で差し替えられます。
bot 自身が音声や映像を出すことはなく、録画にも bot のタイルは映りません。

## セットアップ

必要なもの: engawa に接続できるマシンと Docker（Compose 付き）。小さな機械で十分です。
録画中は 1 会議あたりメモリ 0.5〜1GB、CPU 1〜2 コアほど使います。

```bash
cp .env.example .env
```

`.env` には、`ENGAWA_URL`、`ENGAWA_PASSWORD`（engawa にパスワードがある場合）、`GROQ_API_KEY`、`STROLL_POINTS` を書きます。
`STROLL_POINTS` は、マップの人が少ない場所のタイル座標を `c,r;c,r` の形で並べたものです。座標は engawa のマップ JSON で確認できます。

```bash
make up      # ビルドしてバックグラウンドで起動（落ちても自動で再起動）
make logs    # ログを見る
```

`DELIVERY=local`（既定）の場合、会議ごとに `./data/meetings/<日付 時刻 部屋 (参加者)>/` に保存します
（例: `2026-11-14 1430 会議室1 (アリス、ボブ)`。参加者は 4 人まで名前を並べ、それ以上は「他 N 名」）。

### Google ドライブに届ける

1. Google Cloud で **Google Drive API** を有効にし、**サービスアカウント**を作って、JSON の鍵を
   `config/service-account.json` に置きます。
2. **共有ドライブ**を作り、サービスアカウントのメールアドレスを**コンテンツ管理者**として追加します
   （サービスアカウントは自分の保存容量を持たないので、マイドライブには置けません）。
3. `DELIVERY=drive` にし、`DRIVE_FOLDER_ID` に共有ドライブの ID（URL の末尾）か、その中のフォルダの ID を設定します。
4. `config/recipients.example.json` を `config/recipients.json` にコピーし、engawa の表示名とメールアドレスの対応を書きます。
   `ALLOWED_EMAIL_DOMAINS` には自社のドメインを設定します。これ以外のアドレスには絶対に共有しません。

会議は `<共有ドライブ>/<YYYY-MM>/<YYYY-MM-DD HHMM 部屋 (参加者)>/` に、録画・要約（Google ドキュメント）・
文字起こし（Google ドキュメント）として保存し、会議フォルダを**呼んだ人だけ**に編集権限で共有します。
ドライブへの保存に失敗したときはローカルに残すので、記録が消えることはありません。

## 設定

すべての設定は [.env.example](.env.example) を参照してください。

## 開発

engawa と同じく、すべて Docker 経由で実行します。

| 目的 | コマンド |
|---|---|
| 依存インストール | `make install` |
| 型チェック | `make typecheck` |
| Lint（Biome） | `make lint` |
| テスト | `make test` |

純粋なロジック（通信内容の解釈・状況の追跡・会議の状態遷移・散歩・整形・ドライブ/Groq へのリクエスト組み立て）は
モジュールに分け、`src/__tests__/` でテストしています。

## 制限

- bot は engawa のクライアント UI（要素の ID・ノックの通知）に依存します。engawa のバージョンに合った bot を使ってください。
- engawa はメールアドレスを知らないため、届け先は表示名で引いています。
- bot 1 体が扱えるのは、一度に 1 会議です。
